# Як додати нову статтю в блог · покрокова інструкція для новачка

Ти можеш додавати статті **без знання коду**. Все що треба — створити один файл і написати в ньому текст за шаблоном. Я (Claude) можу зробити це сам — просто скажи "додай статтю про [тема]" і дай ключову інформацію.

---

## Як це працює (швидко)

Кожна стаття — це **один файл** у форматі `.mdx`. Він лежить у:
```
content/blog/<мова>/<slug>.mdx
```

- `<мова>` — це `uk`, `ru` або `en`
- `<slug>` — це частина URL: наприклад файл `tfsa-dlya-ukrayintsiv.mdx` у `content/blog/uk/` стане сторінкою `sky-fort.ca/uk/blog/tfsa-dlya-ukrayintsiv`

Сайт **сам** підхопить новий файл — нічого не треба налаштовувати окремо. Просто комітнеш і за хвилину пост буде онлайн.

---

## Файл-шаблон

Скопіюй цей шаблон у новий файл:

```mdx
---
title: "Точна назва статті"
description: "Один-два рядки які побачить Google у пошуку (160 символів максимум)"
date: "2026-05-25"
author: "Andrii Andriushchenko"
tags: ["TFSA", "newcomers"]
pillar: "TFSA"
ogImage: "/og-image.png"
draft: false
---

> **Коротко:** одне-два речення для AI-краулерів (ChatGPT, Claude, Perplexity). Тут має бути найважливіше повідомлення статті.

## Перший заголовок

Текст параграфа. Можна писати **жирним** або *курсивом*.

> ⚠️ **EMD compliance disclaimer:** освітнє, не інвестиційна рекомендація. NRD #4575551.

### Підзаголовок другого рівня

- Списки роблять так
- Кожен пункт з нового рядка
- Чим коротше тим краще для читання

## Ще один заголовок

Текст другого розділу.

## FAQ

### Перше питання

Відповідь на перше питання.

### Друге питання

Відповідь на друге питання.

## Що далі

[Запишись на безкоштовний 30-хв call](https://calendly.com/andriushchenko-partners/new-meeting).

---

**Key takeaways:**
1. Перший головний висновок.
2. Другий висновок.
3. Третій висновок.
```

## Деталі полів у "шапці" (frontmatter)

Це блок між двома `---` на самому початку. Кожне поле важливе:

| Поле | Що це | Приклад |
|---|---|---|
| `title` | Заголовок статті, з'являється у браузерній вкладці і Google | `"TFSA для українців"` |
| `description` | Короткий опис для Google (показується під заголовком у пошуку). **Макс 160 символів.** | `"Як працює TFSA, скільки room ти маєш, як уникнути 5 помилок."` |
| `date` | Дата публікації у форматі `YYYY-MM-DD` | `"2026-05-25"` |
| `author` | Автор. За замовч. — Andrii | `"Andrii Andriushchenko"` |
| `tags` | Теги через кому в квадратних дужках | `["TFSA", "newcomers", "Канада"]` |
| `pillar` | Один з: `TFSA`, `RRSP`, `FHSA`, `RealEstate`, `ExemptMarket`, `Newcomer`, `Trust` | `"TFSA"` |
| `ogImage` | Картинка яка показується коли посилання шарять у соц. мережах. За замовч. — `/og-image.png` | `"/og-image.png"` |
| `draft` | Якщо `true` — стаття не публікується (можна писати спокійно і не боятись що Google знайде). Коли готово — `false` | `false` |

⚠️ **Дуже важливо**: коли пишеш свою назву файла — використовуй тільки **маленькі англійські літери, цифри і дефіси**. Без пробілів, без апострофів, без кирилиці.
- ✅ `tfsa-dlya-ukrayintsiv-2026.mdx`
- ❌ `TFSA для українців.mdx` (кирилиця і пробіли)
- ❌ `tfsa for newcomers.mdx` (пробіли)

## Покрокова інструкція додати статтю

### Варіант А — попросити мене (Claude) написати

Просто скажи мені:
> "Напиши статтю про [тема] для блогу"

Я зроблю чорнетку через AI-assisted workflow за нашою content-matrix (`docs/tiktok-content-matrix.md`):
- Структура: H1 → intro → ToC → 5-7 H2 → FAQ → CTA
- EMD compliance: ніяких обіцянок дохідності
- Прямі відповіді у перших 100 словах (для AI-краулерів)
- Внутрішні посилання на калькулятори і пов'язані сторінки

Ти потім перечитаєш, поставиш `[VERIFY]` навпроти цифр які треба перевірити, і ми разом доведемо до публікації.

### Варіант B — написати самому

1. **Відкрий папку проекту** у файловому менеджері (Finder).
   - Шлях: `Documents → skyfort-website → content → blog → uk`
2. **Створи новий файл**.
   - Назви його `моя-нова-стаття.mdx` (англ., малі літери, дефіси замість пробілів, обов'язково розширення `.mdx`).
3. **Відкрий файл у текстовому редакторі**.
   - Можна VS Code (рекомендую — підсвітка Markdown), Sublime, навіть TextEdit.
4. **Скопіюй шаблон вище** і встав у файл.
5. **Заміни поля у frontmatter** на свої.
6. **Напиши контент** під другим `---`.
7. **Перевір локально** — у терміналі:
   ```bash
   npm run dev
   ```
   Відкрий у браузері: `localhost:3000/uk/blog` — твоя стаття буде у списку.
8. **Опублікуй** (за деталями див. нижче).

## Як опублікувати написану статтю

Коли файл готовий і ти перевірив у браузері:

```bash
# 1. Подивитись що зміниться
git status

# 2. Додати нову статтю
git add content/blog/uk/моя-нова-стаття.mdx

# 3. Зберегти зміну
git commit -m "blog: add 'Моя нова стаття' (UK pillar TFSA)"

# 4. Відправити на GitHub → автодеплой на sky-fort.ca
git push
```

Через 1-2 хвилини стаття буде на `sky-fort.ca/uk/blog/моя-нова-стаття`.

## EMD compliance — обов'язкові правила (НЕ ПОРУШУВАТИ)

Це регуляторне обмеження. Якщо не дотримаєш — можна отримати штраф або втратити ліцензію.

❌ **Не можна**:
- Обіцяти конкретну дохідність ("ти заробиш 12%", "цей фонд дасть 8%")
- Давати персональну рекомендацію ("тобі треба купити цей фонд")
- Гарантувати результат ("ти точно заробиш мільйон")
- Замовчувати ризики

✅ **Можна** (і треба):
- Розповідати про історичні дані з джерелом ("broad-market ETF історично давали 7-12% за CRA даними")
- Пояснювати концепції ("як працює TFSA")
- Показувати математику ("якщо вкладати X під Y%, через Z років вийде W")
- Давати фреймворки ("3 кроки як перевірити радника")
- Завжди додавати disclaimer

**Шаблон disclaimer-блоку** (вставляй у кожну статтю):

```mdx
> ⚠️ **EMD compliance disclaimer:** Цей текст — освітній матеріал. Це не інвестиційна рекомендація. Для індивідуальних рішень — discovery call з Licensed Dealing Representative (NRD #4575551).
```
